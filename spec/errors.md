# Errors

A failed request returns `{"spec_version", "ok": false, "error": {…}}`
([schema/error.schema.json](schema/error.schema.json)). A failed transaction changes **nothing**: no
op in it is applied, the version does not move, no change set is created.

Every error has `code`, `message` (one short English sentence), `retryable`, `version` (the
document's current version: use it as `base_version` on the retry) and `op_index` (0-based index of
the failing op, or null when the failure is not tied to one op). The other fields are nullable and
filled per code, as listed below; the schema enforces the required ones. The text rendering for
agents is in [projection.md §9](projection.md#9-results-and-errors-as-text). Every code has an
example in [examples/errors/](examples/errors/).

`retryable` means: the same intent can succeed with corrected arguments, without a human. It is
`false` only when no argument change can help.

| Code | Retryable | Required fields |
|---|---|---|
| `STALE_ANCHOR` | yes | `anchor`, `current` |
| `AMBIGUOUS` | yes | `anchor`, `candidates` (≥ 2) |
| `NOT_FOUND` | yes | `what` |
| `IN_FIELD` | yes | `anchor`, `current`, `reason` should be `field_result` |
| `INVALID_OP` | yes | `path`, `usage` |
| `UNSUPPORTED` | yes / no | `reason` |
| `CONFIRM_REQUIRED` | yes | `reason` |
| `PROTECTED` | no | `reason` |
| `LIMIT` | yes | `limit` |
| `BAD_VERSION` | yes | – |
| `CONFLICT` | always yes | – |
| `BAD_PACKAGE` | no | – |
| `INVARIANT` | no | `invariant` |
| `INTERNAL` | always yes | – |

## STALE_ANCHOR

**When.** The target block (or, for a row or cell, its table) changed after `base_version`, and the
op has no `expect` guard that still matches. Every change counts: text, formatting, a revision
added or resolved by someone else.

**Carries.** `anchor`; `current`: the block's projection line at `version` (all lines of the table
for a row or cell anchor).

**Recover.** Re-check the intent against `current`, then resend with `base_version` = `version`. If
the intent no longer fits the new text, tell the user rather than force it.

## AMBIGUOUS

**When.** `find` occurs more than once in the target and the op gave no `occurrence`.

**Carries.** `anchor`; `candidates`: each occurrence with `occurrence` (1-based) and up to 30
characters of context either side.

**Recover.** Pick the occurrence and resend with `occurrence`. If several are meant, send one op per
occurrence, from the last to the first.

## NOT_FOUND

**When.** Something named in the op doesn't exist at `version`. `what` says which:

| `what` | Missing |
|---|---|
| `anchor` | the anchor (deleted, or never existed) |
| `text` | `find` text in the target, compared to the accepted text after NFC and whitespace folding |
| `comment`, `change_set`, `revision` | that id (the engine resolves a `change_set` to its revision ids from its session log; an id it never issued is missing) |
| `asset` | an image asset id not uploaded or expired |
| `style` | a style name or id not defined in the document |
| `op` | an `advanced_op` name not in the catalogue |
| `field` | a `fill` key with no matching placeholder or content control |
| `part` | a package part the op needs (e.g. `numbering.xml` for a list op on a document without one) |

**Carries.** `candidates` when there are close matches (for `text`: the nearest substrings by edit
distance, `occurrence` null; for `anchor`: the blocks that replaced it; for `op`: similar op names
in `context`).

**Recover.** Use a candidate, or `find` / `read_document` to locate the right target.

## IN_FIELD

**When.** The `find` range overlaps a field result or an instruction (`⟪…⟫`). Field results are regenerated by Word, so editing them is lost on the next
update.

**Carries.** `anchor`, `current`, `reason` (`field_result`). Locked controls return `PROTECTED`.

**Recover.** Edit around the field, replace the field with `insert_field`, set a content control
with `fill`, or change the REF's target text instead of the REF.

## INVALID_OP

**When.** The request doesn't match the schema, or the arguments contradict each other (both `after`
and `before`, a range across stories, a range whose start comes after its end, a cell anchor for a
multi-paragraph cell where one paragraph is required, `level` outside 0–8, an image width with no
unit).

**Carries.** `path`: JSON Pointer into the request (`/ops/2/anchor`); `usage`: the op's one-line
signature, as `advanced_op` `help` prints it.

**Recover.** Fix the argument at `path` and resend. Nothing was applied.

## UNSUPPORTED

**When.** The op can't be done the way it was asked. `reason`:

| `reason` | Meaning | Retryable |
|---|---|---|
| `direct_only` | Word can't represent this change as a tracked change (merging cells, some image edits) | yes, with `mode: "direct"` |
| `track_only` | the document or host policy requires tracked changes | yes, with `mode: "track"` |
| `preserve_only` | the target is content the engine keeps but doesn't edit (equation, ink, legacy VML, unknown markup) | no |
| `strict` | Strict OOXML: the engine reads it but writes only transitional | no |
| `not_implemented` | the op is in the catalogue but this engine build doesn't implement it yet | no |
| `unsupported_target` | the anchor names something the op can't act on (a comment in a header, an image outside a paragraph) | yes, with another anchor |
| `merged_cells` | the row, column or range cuts through merged cells | no |
| `nested_table` | the cell holds a nested table | no |
| `no_grid` | the table has no `w:tblGrid` to place a column in | no |
| `unaligned_cells` | the rows' cells don't line up on the grid column asked for | no |
| `uneven_split` | `split_cell` asked for a split other than an even column split or un-merge | yes, with other `rows`/`cols` |

**Recover.** For `direct_only`, ask the user first when the document is under review, then resend
with `mode: "direct"`. For the others, tell the user the part must be changed in Word.

## CONFIRM_REQUIRED

**When.** A beta op runs in track mode without `confirm: true` (`reason: "beta"`). In spec 0.1 these
are `insert_column` and `delete_column`: Word renders tracked cell insertions and deletions
unevenly, so a reviewer may not see them as expected. In direct mode they need no confirmation.

**Carries.** `reason`; `anchor` (the table).

**Recover.** Confirm with the user, then resend with `confirm: true`.

## PROTECTED

**When.** The document or the target can't be changed. `reason`: `signed` (a digital signature
would break), `encrypted`, `irm` (rights management), `document_protection` (`w:documentProtection`
forbids this kind of edit and the host didn't unlock it), `locked_control` (a content control locked
against editing or deletion).

**Recover.** None by retrying. Tell the user; for `document_protection` the host can unlock it.

The engine enforces the declared Word editing restrictions at every transaction operation.
Unenforced restrictions and `edit="none"` remain editable. Enforced `comments` permits comment
operations; `trackedChanges` permits tracked edits and comments but refuses direct edits,
accept/reject and tracking-setting changes. Enforced read-only, form-only, unknown modes and
restricted-formatting policies fail closed when the engine cannot establish permission. The
engine does not resolve permission-range user identities or an allowed-style policy.

Content-locked controls protect their actual subtrees across text, table and review operations;
an unrelated unlocked cell can still change. A deletion-only `sdtLocked` control permits content
edits. Generic operations conservatively refuse deleting a control with locked contents as well
as deleting a deletion-locked control; there is no dedicated operation to remove an entire
content-locked control while preserving the distinction Word exposes. Comment annotations are
allowed without changing locked story contents. These checks honor editing declarations; they
are not authentication, encryption, or proof of signed-package/IRM enforcement.

## LIMIT

**When.** A size or safety limit was hit. `limit` gives `name`, `max` and `actual`. Request limits
(`ops_per_transaction`, `text_chars`, `table_cells`, `image_pixels`, `image_bytes`) are retryable
with a smaller request. Package limits (`zip_entries`, `uncompressed_bytes`, `compression_ratio`,
`xml_depth`, `text_node_bytes`) and `timeout_ms` come from an upload or an operation on a hostile or
huge file and are not fixable by the agent.

**Recover.** Split the transaction or shrink the image. For package limits, tell the user.

The engine enforces `ops_per_transaction` (max 200) before validating any op, so a `LIMIT` error
has `op_index` null. Internally a limit is `Error::LimitExceeded { name, max, actual }`, mapped 1:1 to
`limit`.

## BAD_VERSION

**When.** `base_version` is greater than the document's version, or refers to a version that was
pruned and can no longer be diffed against.

**Recover.** Resend with `base_version` = `version`; re-read the target first if it might have
changed.

## CONFLICT

**When.** Another transaction committed between this one's read of the document and its commit
(optimistic concurrency at the storage layer). Nothing about the request is wrong.

**Recover.** Resend unchanged after a short pause; if a target changed in the meantime, the retry
gets `STALE_ANCHOR` with the current text. The engine retries internally once before returning
`CONFLICT`.

## BAD_PACKAGE

**When.** The uploaded or compared file isn't a usable package: not a zip, missing
`[Content_Types].xml` or the main part, malformed XML in a part the engine must read, an unsupported
format (`.doc`, `.docm` is accepted read-only).

**Recover.** None. Tell the user the file is damaged or of the wrong type.

## INVARIANT

**When.** Applying the op would break one of the package invariants the engine guarantees
(DESIGN §10). Ids, one per invariant there: `rel_targets`, `content_types`, `unique_ids`,
`para_id_range`, `schema_order`, `cell_ends_with_p`, `grid_spans`, `ignorable_namespaces`,
`numbering_order`, `revision_nesting`, `comment_ranges_balanced`, `sectpr_last`, `extent_match`,
`text_space`, `well_formed`. New invariants get new ids in a minor spec version. The check runs
on the result before commit; this is an engine safety net and indicates an engine bug or an
unforeseen document shape.

**Carries.** `invariant`: the invariant's id.

**Recover.** Don't retry the same op. Try a smaller op on a different target, or tell the user.
Hosts should report these.

## INTERNAL

**When.** Anything else. The transaction was rolled back.

**Recover.** Retry once. If it fails again, tell the user; hosts should report it with the request.

## Precedence

When more than one error applies, the engine reports the first in this order, for the first failing
op: `BAD_PACKAGE`, `PROTECTED`, `LIMIT`, `INVALID_OP`, `BAD_VERSION`, `NOT_FOUND`, `STALE_ANCHOR`,
`AMBIGUOUS`, `IN_FIELD`, `UNSUPPORTED`, `CONFIRM_REQUIRED`, `INVARIANT`, `CONFLICT`, `INTERNAL`. Ops
are validated in order, so `op_index` is the lowest failing index.
